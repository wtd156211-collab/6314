# 压缩字典的训练与复用（从 0 实现）

本仓库只有规格与样例数据，没有任何实现代码；实现要新写。

## 1. 范围

目标：用 Python 标准库实现一个压缩字典池——从若干批数据块训练少量共享字典，压缩时逐块复用池内最合适的字典，并保证任何块都能逐字节还原。

要交付：

- 命令行入口 `python -m dictpool`，含 train / pack / unpack / report 四个子命令；
- 池与归档都带内容版本，解压前校验「数据块 ↔ 字典」的对应关系；
- 逐块记录覆盖度、命中与压缩后字节数，并生成单文件静态报告（原生 HTML + ES module，无构建、无外部资源）。

明确不做：

- 不引入第三方依赖、不联网、不加构建步骤；标准库没有字典训练接口，训练逻辑自己写；
- 不做加密、不做网络传输、不做多进程加速；
- 不追求域外数据的压缩收益：允许命中率为 0，但压缩率不得明显劣化，且必须能还原。

## 2. 口径与公式

分块：原始语料在上游按 65536 字节定长切块（最后一块可短），块文件扩展名 `.blk`，块 ID 为文件名去掉扩展名；本工具把块文件当最小单位，不再二次切分。排序一律按文件名字节序升序。

固定参数（不得调参）：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 每块采样 | 8192 B | 取块首，不足则整块 |
| 单批采样上限 | 131072 B | 按块序累加，达到上限即截断，其后块不参与 |
| 片段长度 | 16 B | 采样段内的连续窗口 |
| 片段最小计数 | 2 | 出现次数低于 2 不入选 |
| 字典上限 | 8192 B | 最多 512 个片段 |
| 池容量 | 4 | 字典索引 0..3 |
| 覆盖门限 | 0.25 | 命中判定阈值 |

训练：每个训练批独立训一份字典，索引按命令行给出的批顺序从 0 开始。

1. 采样：按块名升序取每块块首 8192 字节，累加到 131072 字节为止（最后一段可被切断），得到若干采样段。
2. 计数：统计每个采样段内全部连续 16 字节窗口的出现次数，窗口不跨段。
3. 选片：只保留计数 ≥ 2 的片段，按（计数升序，字节升序）排序，取序列末尾 512 个（不足则全取），按该顺序拼成字典字节。
4. 字典 ID = 字典字节的 sha256 十六进制；pool_id = 各字典 sha256 十六进制按索引顺序拼接后再取 sha256。

覆盖度：记 W(d) 为字典 d 的全部 16 字节窗口集合，

- len(b) ≥ 16：ρ = |{ i | 0 ≤ i ≤ len(b)-16，b[i:i+16] ∈ W(d) }| / (len(b)-15)；
- len(b) < 16：b 是 d 的子串取 1，否则取 0。

每块取池内 ρ 最大的字典，并列取索引小者：ρ ≥ 0.25 记命中并用该字典；否则记未命中，按无字典模式压缩。命中率 = 命中块数 / 块数；压缩率 = Σ压缩后字节数 / Σ原始字节数，均按批统计，压缩后字节数含 14 字节块头。

字典版本与数据对应：归档索引记录 pool_id、每块所用字典索引、原始长度与原始 sha256。解压前必须校验 pool_id 与字典 sha256，解压后必须校验长度与 sha256；任何不符即失败退出，不写残缺文件。

## 3. 状态机与数据结构

流程 train → pack → unpack → report，只读写仓库内 `var/`：

- pool（`var/pool/pool.json` + `d0.bin`…）：pool_id 与字典数组 [{index, batch, sample_bytes, dict_bytes, sha256}]；
- archive（`var/archive/index.json` + `<批名>/<块名>.dpk`）：pool_id 与块数组 [{block_id, dict_index|null, raw_len, raw_sha256, packed_len, coverage, hit}]；
- `.dpk`：magic `DPK1`（4 B）+ dict_index（uint16 小端，0xFFFF 表示无字典）+ raw_len（uint64 小端）+ 原始 deflate 载荷。

退出码：0 成功；1 用法错误；2 池或版本不匹配；3 数据校验失败。

## 4. 输入输出与文件格式

在仓库根目录直接执行，无需安装：

    python -m dictpool train  --blocks samples/blocks/logs --blocks samples/blocks/src --blocks samples/blocks/json --blocks samples/blocks/mixed --out var/pool
    python -m dictpool pack   --pool var/pool --blocks samples/blocks/<批名> [--blocks ...] --out var/archive
    python -m dictpool unpack --pool var/pool --archive var/archive --out var/restored
    python -m dictpool report --archive var/archive --out var/report/index.html

- `--blocks` 可重复，批名取目录名；归档内块 ID 为 `<批名>/<块名>`；
- 压缩：level=9、wbits=-15（原始 deflate）、默认 memLevel 与策略，zdict 为所选字典；无字典模式不传 zdict；
- 解压：`var/restored/` 下的目录与文件必须与原块逐字节一致；
- 报告：单个 HTML 文件，内联 JSON 与 `<script type="module">` 脚本，不请求任何外部资源，可直接用 file:// 打开，至少展示每批命中率与压缩率、逐块明细（块 ID、字节数、字典索引、覆盖度、压缩后字节、是否命中）；
- JSON 一律 UTF-8；除 `var/` 外不写文件。

## 5. 性能与验收口径

- 训练：4 批、采样合计 380 KiB，耗时 ≤ 5 s；
- 压缩与解压：本样例（约 0.67 MiB）各 ≤ 20 s，报告生成 ≤ 5 s（≤ 5000 块）；
- 内存：tracemalloc 峰值 ≤ 128 MiB，且输入翻倍后峰值增幅 ≤ 32 MiB（不得随总量线性增长）；单块上限 8 MiB；
- 验收顺序：
  1. `samples/expected/pool.tsv`：每份字典的采样字节数、字典字节数、sha256 与实现产出一致；
  2. `samples/expected/eval.tsv`：逐批命中率 ≥ 下限、压缩率 ≤ 上限；
  3. 全部块解压后逐字节一致（含 1 B 与 128 KiB 块）；
  4. 篡改字典或归档内容后解压必须以退出码 2 或 3 失败；
  5. 除标准库外无 import，运行期间无网络访问。

## 6. 样例说明

`samples/blocks/` 共 6 批 76 块（约 0.67 MiB）：

| 批次 | 角色 | 块数×字节 | 说明 |
| --- | --- | --- | --- |
| logs | 训练 | 24×8192 | 同类文本：访问日志 |
| src | 训练 | 20×8192 | 同类文本：伪代码 |
| json | 训练 | 12×5120 | 同类文本：JSON 记录 |
| mixed | 训练 | 8×12288 | 异构混排：日志 + 代码 + JSON |
| drift | 评估 | 6×8192 | 与训练样本风格不同：英文散文、CSV、base64 |
| size | 评估 | 1/15/16/64/1024/131072 | 短块与长块，覆盖片段边界 |

4 个训练批正好用满池容量；drift 与 size 不参与训练，用来验证跨批复用与边界处理。样例中 1 KiB 日志块用池内字典后比无字典小 29.8%，16 B 块小 40%，各训练批自压也有 7.6%～20.9% 的收益；drift 全部未命中，回落到无字典路径且不劣化。`samples/notes.md` 记录了为什么要把字典收成一个池。期望基线见 `samples/expected/`，压缩率上限含 10% 余量以吸收 zlib 版本差异。
